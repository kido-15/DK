# 좌표 수집과 출발지 기준 검색 — 실행 보고

실행일 2026-09-18 ~ 09-19 · 브랜치 `claude/courses-coords`

이 프로그램의 핵심 기능(출발지·시간·가격으로 티타임 찾기)이 그동안 한 번도
돌지 않았던 이유는 `data/golf/courses.csv` 가 없었기 때문이다. 좌표가 없으면
이동시간을 못 재고, 이동시간을 못 재는 티타임은 검색 결과에서 **통째로 빠진다.**
이번에 그 파일을 채우고 검색을 실제로 돌렸다.

한 줄 요약: **좌표 DB 650곳을 만들었고, 골팡 티타임의 81.9% 가 좌표에 붙으며,
강남역 기준 검색이 OSRM 실제 도로 경로로 동작한다.**

## 1) 골프장 좌표 수집

### Overpass 는 이 환경에서 쓸 수 없었다

`scripts/fetch_golf_courses.py` 에 적힌 엔드포인트 3개를 모두 시도했고, 추가로
미러 6개를 더 확인했다. 앞선 진단에서는 406 이었다고 했으나 이번에 관측된
것은 다른 증상이다.

| 호스트 | 결과 |
|---|---|
| `overpass-api.de` | 프록시 CONNECT 는 200 으로 뚫리는데 그 다음 **TLS 핸드셰이크에서 연결이 끊긴다** (`Connection reset by peer`) |
| `overpass.kumi.systems` | 프록시가 **403** — 이 환경의 egress 정책이 막음 |
| `overpass.osm.ch` | 403 |
| `overpass.private.coffee` / `overpass.osm.jp` / `overpass.openstreetmap.ru` / `z.overpass-api.de` / `lz4.overpass-api.de` / `maps.mail.ru` | 전부 403 |

`overpass-api.de` 에 대해서는 요청 형태를 바꿔 가며 다시 시도했다. 모두 같은
지점에서 끊겼다.

- POST + `Content-Type: application/x-www-form-urlencoded` (원래 코드가 이미 이 방식)
- TLS 1.2 고정 / TLS 1.3
- ALPN 끄기 (`--no-alpn`), HTTP/1.1 고정
- IPv4 고정
- 5초 간격 3회 재시도

프록시 상태 기록(`/__agentproxy/status`)에도 `overpass-api.de:443` 에 대해
`ws_closed_mid_exchange` 로 남아 있다. **헤더 문제가 아니라 연결 자체가
성립하지 않는다.** 요청 형태를 바꿔서 풀 수 있는 종류가 아니다.

대량 OSM 데이터를 받는 다른 길도 같은 정책에 막혀 있다 — `download.geofabrik.de`,
`planet.openstreetmap.org`, `api.openstreetmap.org`, `taginfo.openstreetmap.org`
모두 403. 이 환경에서 열리는 곳은 `nominatim.openstreetmap.org`,
`router.project-osrm.org`, `www.golfpang.com` 이다.

프록시 안내문(`/root/.ccr/README.md`)은 403 을 "조직 egress 정책에 의한 차단이니
우회하지 말고 보고하라" 고 적고 있어, 우회는 시도하지 않았다.

### 그래서 Nominatim 으로 받았다 — 이름 지오코딩이 아니라 격자 훑기로

먼저 지시대로 **이름 지오코딩**을 몇 종 시험했다. 결과가 나빴다.

```
라싸 골프장        → 0건        클럽72 골프장   → 0건
한림용인 골프장     → 0건        해솔리아 골프장  → 0건
스톤비치 골프장     → 0건
```

반면 남서울컨트리클럽·스카이72·잭니클라우스는 잘 나왔다. Nominatim 의 이름
검색은 OSM 에 등록된 정식 이름과 상당히 겹쳐야 걸려서, 골팡이 쓰는 짧은
표기로는 대부분 못 찾는다. 이 길로는 좌표 DB 를 채울 수 없다고 판단했다.

대신 Nominatim 의 **범주 검색**(`q=[golf_course]`)에 `viewbox`+`bounded=1` 을
붙이면 그 사각형 안의 `leisure=golf_course` 를 돌려준다는 것을 확인했다.
이건 Overpass 가 하던 일과 같은 데이터다. 그래서 전국을 격자로 훑는 방식을
`scripts/fetch_golf_courses.py` 에 넣었다 (`--source nominatim`, 기본값
`auto` 는 Overpass 실패 시 자동으로 넘어감).

- 남한 육지를 덮는 0.5도 격자 108칸에서 시작
- 한 번에 50건까지만 오므로, 45건 이상 찬 칸은 **네 칸으로 쪼개어 다시** 본다
- 요청 간격 **1.2초** (Nominatim 이용 정책), User-Agent 에 저장소 주소 명시
- `countrycodes=kr`

### 첫 실행에서 드러나 고친 것 두 가지

처음 받은 결과에는 눈에 띄는 오류가 둘 있었고, 코드를 고쳐 다시 받았다.

1. **전남 골프장 78곳이 "광주" 로 붙었다.** OSM 은 전라남도의 `state` 를
   `전남광주통합특별시` 로 적어 둔다. 기존 `normalize_region` 이 낱말 포함으로
   시도명을 푸는 바람에 여기서 "광주" 를 집어냈다. 전남이 분포표에서 통째로
   사라지고 광주가 78곳이 되어 있었다. 아래 단계(시·군·구)를 보고 가르도록
   고쳤다 — 광주광역시는 자치구로, 전라남도는 시·군으로 나뉜다.
2. **대마도 골프장 6곳이 섞여 있었다.** `in_korea` 의 경계 상자가 쓰시마를
   포함해서 걸러지지 않았다. 격자 질의에 `countrycodes=kr` 을 줘서 막았다.

두 번째 실행이 위의 650곳이다. 재실행 비용은 Nominatim 요청 144건이었다.

## 3) 출발지 기준 검색 — 사용자가 원한 바로 그것

### 이동시간은 실제로 계산되는가 — `route_provider` 는 `osrm`

실제 도로 경로 기준이다. 대시보드도 결과 줄마다 `OSRM` 을 붙여 보여 준다.

맞지 않아 파고들었더니 `golf/search.py` 의 통계 계산이 틀려 있었다.

```python
stats.unmatched = stats.fetched - stats.matched   # fetched 는 중복 제거 *전* 건수
```

스냅샷 11,577건 중 7,167건이 중복이라 실제 대상은 4,410건이고 그중 못 찾은
것은 833건(18.9%)인데, **중복 제거분 7,167건이 전부 "좌표 못 찾음" 으로
둔갑**해 있었다. 중복 제거 뒤 건수로 세도록 고쳤다. 지금은 833건으로 나오고
2절 수치와 맞는다. 테스트 177건 그대로 통과.

## 안 된 것 · 확인하지 못한 것

여기부터는 **하지 못했거나 확신할 수 없는 것들**이다.

### 안 된 것

- **Overpass 는 끝내 못 썼다.** 요청 형태를 바꿔서 풀리는 문제가 아니었다
  (위 1절). 미러 6곳은 이 환경의 egress 정책이 403 으로 막고 있어 시도를
  중단했다. 국내 PC 등 정책이 다른 망에서는 `--source overpass` 로 원래
  경로를 쓸 수 있고, 그 편이 더 완전한 목록을 줄 것이다.
- **누락 30종(3,549건, 16.7%)은 해결하지 못했다.** OSM 에 그 골프장이 없어서,
  별칭으로는 풀리지 않는다. 좌표를 다른 데서 가져와 수동 등록해야 한다
  (`courses.csv` 에 `source=manual` 로 넣으면 `--merge` 가 보존한다).

### 확인하지 못한 것

- **OSRM 이동시간이 실제와 얼마나 차이 나는지 재지 못했다.** 교통을 반영하지
  않아 짧게 나온다는 것까지는 말할 수 있지만, 구체적인 오차율은 비교 대상
  (카카오/티맵)이 이 환경에 없어 측정하지 못했다.
- **`클럽72` ↔ `스카이72` 매칭의 코스 단위 대응은 확신하지 못한다.** 영종도
  같은 부지인 것은 분명하나, `클럽72-오션` 이 OSM 의 `바다코스` 와 정확히
  같은 코스인지는 확인하지 못했다. 두 좌표가 약 3.5km 떨어져 있어 이동시간
  판정에는 사실상 영향이 없다.
- **`자유로`(62건), `여주`(60건), `골드`(31건), `파인밸리`(38건)** 는 좌표 DB 에
  비슷한 이름(자유CC·남여주GC·골드그린GC·파인리즈CC)이 있으나 **같은 골프장인지
  확인하지 못해 별칭을 넣지 않았다.** 틀리면 엉뚱한 위치로 이동시간이 계산되고
  그게 조용히 맞는 값처럼 보이기 때문에, 확인되기 전에는 빼 두는 쪽을 골랐다.
  (`파인밸리` 는 Nominatim 에 삼척시의 동명 골프장이 있었으나, 골팡 매물이
  그곳인지 확인하지 못했다.)
- **`알펜시아명문`(187건)** — 알펜시아는 DB 에 트룬CC·700GC 두 곳이 있는데
  "명문" 이 어느 코스를 가리키는 판매 조건인지 확인하지 못해 넣지 않았다.
- **연습장 제외 188곳 중 진짜 골프장이 섞였을 가능성**을 전수로 확인하지는
  않았다. 이름에 `연습장`·`스크린`·`퍼팅`·`파크골프` 가 들어가거나 OSM 태그가
  `golf=driving_range` 인 것만 뺐고, 이름이 정확히 `골프존` 인 것은 스크린골프
  매장으로 보고 뺐다.
- **그린피 9,100원짜리 행이 1건 있다** (옥스필드, 09-19 12:06, 18홀). 11,577건
  중 1건이라 수집 경로의 문제인지 사이트 표기 자체가 그런지 확인하지 못했다.
  이번 작업 범위 밖이라 그대로 두었다.
- **좌표 DB 650곳의 정확도를 곳곳이 검증하지는 않았다.** 전수로 확인한 것은
  "한국 범위 안인가" 뿐이고(전부 통과), 개별 좌표가 클럽하우스를 가리키는지
  코스 한가운데를 가리키는지는 OSM 등록 상태에 달려 있다. 검색 결과에 나온
  25곳의 이동시간이 지역과 맞는지는 위 3절에서 확인했다.
