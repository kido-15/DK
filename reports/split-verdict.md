## 판정 — 분할을 유지한다

차이가 매물 드나듦으로 설명되지 않는다. 두 실행 사이 기준값은 7,814 → 7,815 로 사실상 제자리였고
전체 16분 동안에도 7,786 → 7,829 (+43) 만 움직였다. 그런데 한쪽에만 있는 행은 89 대 352 로
263건이나 나눈 쪽으로 쏠렸다. 드나듦이라면 대칭이어야 할 차이가 아니다.
각 실행이 자기 직전·직후 기준값에 대해 매긴 확보율도 96% 대 99% 로 갈렸고,
나누지 않은 쪽에서만 중복이 332건(나눈 쪽 76건) 걸러진 것 — 페이지 경계가 계속 밀렸다는 흔적 — 도
설정에 적힌 메커니즘(긴 묶음일수록 받는 사이 목록이 흔들린다)과 같은 방향이다.

비용은 요청 약 +7%, 시간 약 +80초다. 하루치에서 약 260건(3%p)을 더 건지는 대가로는 싸다.

## 확인하지 못한 것

- **나눈 쪽의 요청 횟수·소요 시간은 실행 로그에서 놓쳤다.** 화면 출력을 자르는 바람에 합계 줄이 남지
  않았다. 표의 86회는 직후 지역별 `총 N`(2,968 / 1,606 / 2,370 / 837 / 50)으로
  `올림(N/100)+빈 페이지 1` 을 더해 재구성한 값이고, 480초는 실행 앞뒤 시각의 차다. 실측이 아니다.

  다시 확인하지 않았다. 두 실행 사이 기준값이 +1 이었던 점이 순서 효과를 줄이기는 하지만 없앴다고
  말할 수는 없다.
- 두 방식 모두 기준값에 100% 도달하지 못한 나머지(나눈 쪽 기준 약 70~84건)가 무엇인지는 보지 않았다.
