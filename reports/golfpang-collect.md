## 1️⃣ robots.txt 확인 — 먼저 읽어 주세요

지시하신 `m.golfpang.com` 은 **쓰지 않았습니다.** robots.txt 가 막고 있기 때문입니다.

```
$ curl https://m.golfpang.com/robots.txt      → HTTP 200
User-agent: *
Disallow: /m/
```

그런데 모바일 사이트는 **내용 전체가 `/m/` 아래에** 있습니다. 랜딩 페이지에서 뽑은 링크가
`/m/round/booking_main.do`, `/m/round/tourInnerList.do`, `/m/join/login.do` … 전부 `/m/` 입니다.
티타임 목록도 `/m/round/bookListTmp.do` 입니다 (랜딩 페이지의 `selectQuick()` 함수 안에 있음).

즉 **모바일 사이트에서 티타임을 수집하는 것은 robots.txt 가 금지한 경로를 건드리는 일**입니다.
"robots.txt 를 먼저 확인하고 금지된 경로는 건드리지 마세요" 라는 지시를 지키기 위해
`/m/` 는 robots.txt 와 랜딩 페이지 1회 조회 외에는 요청하지 않았습니다.

대신 **PC 사이트 `www.golfpang.com`** 를 썼습니다. 같은 티타임 데이터를 제공하고, robots.txt 상 제한이 없습니다.

```
$ curl https://www.golfpang.com/robots.txt    → HTTP 200
User-agent:Yeti
Disallow:
User-agent: naverbot
Disallow:
... (Googlebot, bingbot, AhrefsBot, PetalBot 등 20개 봇이 같은 형태)
```

`User-agent: *` 그룹이 **아예 없고**, 명시된 봇들은 모두 `Disallow:` (빈 값 = 전체 허용)입니다.
RFC 9309 기준으로 어느 그룹에도 해당하지 않으면 적용되는 규칙이 없으므로 제한 없음으로 판단했습니다.

> 참고: `golfpang.com`(www 없음)은 인증서 이름이 맞지 않아 HTTPS 연결이 되지 않습니다.
> 인증서 검증을 끄지 않았으므로 이 호스트는 확인하지 못했습니다.

## 2️⃣ 티타임 목록이 나오는 실제 주소

### 사람이 보는 화면 (수집에 사용한 주소)

```
https://www.golfpang.com/web/round/booking_list.do?rd_date=2026-09-19
```

- `rd_date=YYYY-MM-DD` — 날짜 (필수는 아니고, 없으면 기본값)
- `sector=<번호>` — 지역. **비워 두면 전국 전체**가 나옵니다.
  - `1`=강북/경춘, `4`=충청, `5`=한강이남, `8`=원주/영동, `16`=영호남/제주
  - (지역 이름은 화면의 `sct` 드롭다운에서, 번호는 날짜 칸의 `selectQuick()` 인자에서 확인)

**로그인은 하지 않았습니다.** 로그인 없이 목록 전체가 보입니다.

### 거기까지 가는 데 필요한 조작

1. `https://www.golfpang.com/` 는 0.2초 뒤 `https://www.golfpang.com/index.htm` 으로 자바스크립트 이동합니다.
   (모바일 UA 로 접속하면 `m.golfpang.com/m/AppGuide.do` 로 보내므로 **PC UA 가 필요**합니다.)
2. 메인 화면의 날짜 칸을 누르면 `selectQuick(rdate, sector)` → `#frm` 을 `/web/round/booking_list.do` 로 submit.
3. `booking_list.do` 는 **빈 표만 있는 껍데기**입니다. 열자마자 `$(document).ready` 안에서 `goSubmit()` 이 돌고,
   그 ajax 응답이 `#tblList` 안에 채워지면서 비로소 티타임이 보입니다.
4. 이 ajax 가 **약 8~10초** 걸립니다. 그 전에 읽으면 0건이 나옵니다. (아래 4️⃣ 참고)

### 목록을 직접 주는 내부 주소 (JSON 아님)

```
POST https://www.golfpang.com/web/round/booking_tblList.do
Header: X-Requested-With: XMLHttpRequest
Body(form-urlencoded):
  pageNum=1        페이지 번호 (한 페이지 100건)
  rd_date=2026-09-19   날짜
  ampm=            시간대 (전체/오전/오후/야간 — 빈 값이면 전체)
  sector=          지역 번호 (빈 값이면 전국)
  clubname=        골프장 코드
  sector2= sector3=  영호남/제주 선택 시 쓰는 하위 지역
  cdOrder=         정렬
```

**응답은 JSON 이 아니라 HTML 조각**입니다(`<table class="type2">` 통째로). 그래서 explore.py 의
"① 페이지가 부른 JSON 요청" 은 "없습니다" 로 나옵니다 — **JSON API 는 찾지 못했습니다.**
네트워크 기록상 골팡은 목록을 JSON 으로 주고받지 않습니다.

이 주소는 curl 로 확인만 했고, 실제 수집은 지시하신 대로 브라우저(auto_collect.py)로 했습니다.

## 3️⃣ 목록 HTML 구조

```
#tblList
└─ table.type2
   ├─ thead > tr > th × 12     ← 칸 이름이 여기 적혀 있음
   └─ tbody > tr × 100         ← 반복 요소 (한 페이지 100건)
         └─ td × 12
```

`<tr>` 하나가 티타임 하나입니다. `id="tr_220011811"` 형태의 매물 번호가 붙습니다.

| td 번호 | thead 이름 | 내용 | 예시 |
|---|---|---|---|
| 0 | 지역 | 권역 | `강북/경춘` |
| 1 | 부킹일 | 날짜 | `09월20일 (일)` |
| 2 | **티타임** | 시각 | `17:27` |
| 3 | 포함 | 식사·간식 아이콘 | `<img alt="식사">` |
| 4 | **골프장** | 골프장 이름 | `필로스` |
| 5 | 홀수 | 홀 수 | `18홀` |
| 6 | (없음) | 딜러지원 배지 | 대부분 빈 칸 |
| 7 | **그린피** | 가격 | `<span class="price">120,000</span>원` |
| 8 | (없음) | 판매처 | `골팡 당근`, `골팡 컨시드` |
| 9 | 캐디유무 | 캐디 | `노캐디`, `일반캐디` |
| 10 | 구분 | 거래 형태 | `양도` |
| 11 | 조회 | **조회수** | `1`, `7`, `62` |

⚠️ 마지막 칸은 **잔여 인원이 아니라 조회수**입니다. 남은 자리 수로 읽으면 안 됩니다.
(현재 수집기는 이 칸을 쓰지 않아 `slots` 는 비어 있습니다.)

### 셀렉터 요약

- 반복 요소: `#tblList table.type2 tbody tr`
- 골프장명: `td:nth-child(5)`
- 시각: `td:nth-child(3)`
- 가격: `td:nth-child(8)` (안쪽 `span.price`)
- 날짜: `td:nth-child(2)` — **각 행이 자기 날짜를 들고 있습니다.** (검증에 유용, 4️⃣ 참고)

### 날짜 선택 UI

```html
<div onclick="selectQuick('2026-09-19','5')">2917</div>
```

- 인자는 `(날짜, 지역번호)` 2개입니다.
  (모바일 사이트의 `selectQuick('1','2026-09-20','16')` 3개 인자와 **다릅니다.**)
- 보이는 글자는 날짜가 아니라 **그 날짜·그 지역의 매물 수**입니다.
- 이 달력 띠에서 날짜별 전체 매물 수를 그대로 읽을 수 있습니다:

| 날짜 | 한강이남 | 강북/경춘 | 충청 | 원주/영동 | 영호남/제주 |
|---|---|---|---|---|---|
| 09/18 (금) | 872 | 705 | 1233 | 498 | 62 |
| 09/19 (토) | 2917 | 1985 | 3298 | 1026 | 86 |
| 09/20 (일) | 3120 | 2289 | — | — | — |

- 날짜를 눌러도 **주소는 바뀌지 않습니다** (ajax). 그래서 "지금 화면이 몇 일자인지"는
  주소가 아니라 표 안의 부킹일 칸으로만 알 수 있습니다.

- **가격 없음 2건** (`green_fee = -1`): 골팡이 `가격문의` 로 표시하는 매물입니다.
  버그가 아니라 사이트에 실제로 값이 없는 경우입니다. 목록을 다시 받아 확인했습니다:
  `['한강이남','09월19일 (토)','17:59','','빅토리아-퍼9','18홀','','가격문의']`

### 개인정보 확인

커밋 전 CSV 를 검사했습니다. 전화번호·이메일·닉네임·번호류 **0건**입니다.
CSV 칸은 `course_name, play_date, tee_time, green_fee, source, booking_url, slots, hole_info` 뿐이고,
로그인을 하지 않았으므로 예약자 정보가 섞일 여지가 없습니다.
(`골팡 당근`, `골팡 세종` 같은 판매처 표시는 골팡 내부 판매 채널 이름이며 CSV 에 담기지 않습니다.)

## 6️⃣ 고친 코드와 이유

세 파일을 고쳤습니다. 모두 **골팡 전용 분기가 아니라** 일반적인 개선입니다.
기존 테스트 134개는 그대로 통과합니다.

### (1) `golf/extract.py` — 표 머리글로 칸을 알아낸다

**증상.** 골프장 이름 자리에 지역 이름이 들어왔습니다. 100건 중 절반쯤이 이랬습니다.

```
name='강북/경춘'   ← 실제 골프장은 '필로스'
name='강북/경춘'   ← 실제 골프장은 '몽베르(대중제)'
```

**원인.** `extract_course_name()` 은 행 안의 글자들을 점수 매겨 고릅니다.
`CC`·`골프`·`밸리` 같은 단서가 있으면 +10 인데, `한강이남`(지역)과 `사우스스프링스`(골프장)는
**둘 다 단서가 없어 동점**입니다. 동점이면 먼저 나온 것이 이기고, 지역 칸이 골프장 칸보다 앞에 있어
항상 지역이 뽑혔습니다. `이천실크밸리`처럼 `밸리`가 들어간 이름만 우연히 맞았습니다.

**수정.** 추측하기 전에 **표 머리글을 읽습니다.** 목록이 `<table>` 이고 `<thead>` 에
`골프장`·`티타임`·`그린피`·`부킹일` 이라고 적혀 있으면 그 칸 번호를 그대로 씁니다.

- 새 함수 `table_column_map(nodes)` — `<th>` 글자를 우리 필드 이름에 대응시킴
- `<th>` 수와 행의 `<td>` 수가 다르면 칸 번호를 믿을 수 없으므로 **빈 값을 돌려주고 기존 방식으로 돌아갑니다**
- 머리글이 없는 사이트(`<div>` 목록 등)는 동작이 전혀 바뀌지 않습니다

결과: 지역 이름 유출 0건, 골프장 60곳이 제대로 잡힙니다.

### (2) `golf/interact.py` — 목록이 바뀔 때까지 기다린다

**증상.** 날짜를 눌렀는데 **이전 날짜의 목록**을 읽었습니다. 처음 조사에서 09-19 와 09-20 의
상위 3건이 글자 하나까지 똑같이 나온 것이 그 흔적입니다.

**원인.** 골팡은 날짜를 눌러도 화면이 바로 안 바뀝니다. 실제로 재 보니 **약 4초** 걸립니다.

```
클릭 +1.1초 → 09월19일 100건   ← 아직 이전 날짜
클릭 +2.1초 → 09월19일 100건
클릭 +3.1초 → 09월19일 100건
클릭 +4.1초 → 09월21일 100건   ← 이제 바뀜
```

기존 `_wait_settle()` 은 networkidle 을 1.8초만 기다리고 바로 비교해서, 저 3초 구간을
"안 바뀌었다"고 판단하거나 이전 목록을 그 날짜 것으로 읽었습니다.

**수정.**
- `_wait_for_change()` 추가 — 목록이 실제로 달라질 때까지 최대 8초 기다림
- `_wait_until_stable()` 추가 — 그리는 도중을 읽지 않도록 변화가 멈출 때까지 기다림
- `wait_for_list()` 추가 — 첫 화면에서 목록이 그려질 때까지 기다림 (골팡은 8~10초 걸림)

**속도 문제와 그 처리.** 위 변경만 넣으니 기존 테스트가 40초 → 199초로 느려졌습니다.
클릭해도 아무 일도 안 일어나는 후보마다 8초씩 버렸기 때문입니다.
그래서 **뭔가 오갔는지 먼저 봅니다** — `performance.getEntriesByType('resource').length` 로
클릭 전후 요청 수를 비교해, 화면도 그대로이고 오간 것도 없으면 그 클릭은 헛클릭으로 보고
기다리지 않고 넘어갑니다. `wait_for_list()` 에도 같은 조용함 판정을 넣었습니다.
→ 테스트 40초 → **58초** (늘어난 18초는 실제로 필요한 검증 시간)

### (3) `golf/sources/browser_source.py` — 읽은 것이 그 날짜인지 확인한다

**증상 ①** 첫 날짜만 0건. **증상 ②** 첫 날짜가 "로그인해야 목록이 보이는 화면입니다" 로 잘못 판정.

**원인.** 날짜를 누르면 골팡은 `$("#tblList").empty()` 로 **목록을 먼저 비우고** 그 다음 받아옵니다.
비어 있는 3초 사이에 읽으면 티타임이 0건이고, 페이지에 로그인 링크는 있는데 시각이 하나도 없으니
`detect_login_wall()` 이 로그인 벽으로 오판했습니다.

**수정.** 목록을 읽은 뒤, 각 행이 들고 있는 날짜가 **요청한 날짜와 맞는지 확인**하고,
맞지 않거나 0건이면 1초 쉬고 다시 읽습니다 (최대 8회).
행에 날짜가 안 적힌 사이트는 확인할 방법이 없으므로 그냥 넘어갑니다.
첫 화면 로딩에도 `interact.wait_for_list()` 를 붙였습니다.

이 확인이 없으면 **어제 목록을 오늘 것으로 저장**하게 됩니다. 조용히 틀리는 종류의 버그라
값을 늘리는 것보다 확인을 넣는 쪽을 택했습니다.

## 7️⃣ 안 된 것 / 하지 않은 것

### ❌ 모바일 사이트(`m.golfpang.com`)에서 수집하지 못함
robots.txt 가 `/m/` 를 금지합니다. 1️⃣ 참고. **지시받은 사이트를 쓰지 못한 것이므로 판단을 확인해 주세요.**
`/m/` 도 수집해야 한다면 별도로 말씀해 주시면 됩니다.

### ⚠️ 날짜당 100건까지만 수집 (1페이지)
사이트는 09-19 에만 9,646건이 있는데 100건만 가져왔습니다.
`booking_tblList.do` 의 `pageNum` 으로 페이지를 넘길 수 있고 2·3페이지가 다른 내용인 것도 확인했지만,
**auto_collect.py 의 브라우저 방식에는 페이지 넘기기가 없습니다.**
전량 수집하려면 `config/sources.json` 에 `booking_tblList.do` 를 POST 소스로 등록하는 편이 맞습니다
(이 저장소의 `golf/sources/web_source.py` 가 POST·페이지 넘기기·robots 확인·요청 간격을 이미 지원합니다).
이번 작업 범위를 넘어선다고 보아 하지 않았습니다.

### ❌ JSON API 를 찾지 못함
골팡은 목록을 JSON 으로 주지 않습니다. `booking_tblList.do` 가 HTML 조각을 돌려줍니다.
"못 찾은 것"이 아니라 "없는 것"으로 보이지만, 앱 전용 API 가 따로 있을 가능성은 확인하지 못했습니다.

### ⚠️ `slots`(잔여 인원) 비어 있음
표의 마지막 숫자 칸은 잔여가 아니라 조회수입니다. 잘못 넣느니 비워 두었습니다.
잔여 인원은 목록에 없고, 매물을 눌러야 나오는 `showCon(매물번호)` 상세에 있을 수 있습니다(확인 안 함).

### ⚠️ 테스트 1회 일시 중단
`tests/test_browser_choice.py` 가 전체 연속 실행 중 한 번 300초 제한에 걸렸습니다.
단독으로 3회 재실행하면 매번 9.6초에 통과합니다. 브라우저 여러 개를 연달아 띄우면서 생긴
일시적 현상으로 보이지만, **원인을 확정하지는 못했습니다.**

### 요청 간격
- curl 확인은 매 요청 사이 2초 이상 쉬었습니다.
- 브라우저 수집은 날짜 하나에 10초 이상 걸려 목록 요청 간격은 충분합니다.
- 다만 브라우저가 페이지를 열 때 딸려 나가는 css·이미지 요청까지 간격을 둔 것은 아닙니다.
- 사이트에는 **아무것도 제출하거나 예약하지 않았고, 로그인도 하지 않았습니다.** 읽기만 했습니다.
- `HTTPS_PROXY` 를 해제하거나 TLS 검증을 끈 적이 없습니다. Chromium 에는 지시대로
  `certutil` 로 프록시 CA 를 NSS DB 에 등록해서 검증을 켠 채로 접속했습니다.

**확인했습니다. 현재 주소는 `www.kakao.golf` 입니다.** (`golf.kakao.com` 이 아니라 `.golf` TLD)

| 항목 | 결과 |
|---|---|
| `golf.kakao.com` | DNS 이름 없음 (확인) |
| `m.golf.kakao.com` | DNS 이름 없음 (확인) |
| **`www.kakao.golf`** | **DNS 정상** — 3.169.202.101, 3.169.202.43 |
| `reserv.kakao.golf` | **DNS 정상** — 99.84.105.29, 99.84.105.37 (예약 화면) |

도메인을 무작위로 두드리지 않았습니다. 웹 검색으로 공식 주소를 확인한 뒤 그 이름만 DNS 로 조회했습니다.

**다만 이 환경에서는 접속되지 않습니다.** 프록시가 막습니다:

```
$ curl https://www.kakao.golf/
* Establish HTTP proxy tunnel to www.kakao.golf:443
< HTTP/1.1 403 Forbidden
```

이 환경의 네트워크 정책에 이 호스트가 없어서입니다(골팡은 열려 있습니다).

## 9️⃣ 재현 방법

```bash
# 준비 (이 환경 기준)
apt-get install -y libnss3-tools
certutil -d sql:$HOME/.pki/nssdb -A -t "C,," -n ccr-agent-proxy -i /root/.ccr/agent-proxy-ca.crt
pip3 install playwright        # playwright install 은 하지 않음 — /opt/pw-browsers 사용

# 조사
python3 scripts/explore.py "https://www.golfpang.com/web/round/booking_list.do?rd_date=2026-09-19" \
    --days 3 --wait 9000

# 수집
python3 scripts/auto_collect.py "https://www.golfpang.com/web/round/booking_list.do?rd_date=2026-09-19" \
    --days 3 --start 2026-09-19 --wait 9000 --source golfpang \
    --save reports/golfpang-teetimes.csv
```

`--wait 9000` 이 필요합니다. 기본값 4000 으로는 첫 화면의 ajax 가 아직 안 끝나 첫 날짜를 놓칩니다.
