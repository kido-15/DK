- 대상: `POST https://www.golfpang.com/web/round/booking_tblList.do` (PC 사이트만 사용)
- 도구: `scripts/collect_full.py` + `config/sources.golfpang.json` (커밋 ef09ccc)
- 검증 수행일: 2026-09-18
- 로그인하지 않았고, 예약·신청·제출 버튼은 누르지 않았습니다. 목록 조회(POST)만 했습니다.

> 이 문서는 작업 중 갱신됩니다. 3) 전량 수집 결과는 실행이 끝난 뒤 채웁니다.

## 1. 설정에서 고친 것

**아무것도 고치지 않았습니다. 추측한 선택자가 그대로 맞았습니다.**

실제 응답 조각을 `curl` 로 1회 받아(145,657바이트) 표 구조를 눈으로 확인했습니다.

- `<tbody>` 는 **있습니다**. (`list_selector` 가 `table.type2 tr` 라 있든 없든 영향은 없습니다.)
- `<table class="type2">` 는 조각 안에 **1개뿐**이고, `<tr>` 은 101개(헤더 1 + 데이터 100)입니다.
- 실제 칸 순서(`<thead>` 의 `<th>` 기준, 12칸):

  | 칸 | 머리글 | 설정에서 쓰는가 |

  | 3 | 티타임 | `tee_time` ✅ |
  | 4 | 포함 | — |
  | 5 | 골프장 | `course_name` ✅ |
  | 6 | 홀수 | `hole_info` ✅ |
  | 7 | (빈 칸) | — |

골프장 자리에 `한강이남` 같은 지역명이 아니라 실제 골프장 이름이 들어옵니다.

오늘 기준으로는 맞지만, 연말에 다음 해 날짜를 조회하면 틀릴 수 있는 자리입니다
(이번 검증 범위에서는 확인하지 않았습니다).

## 2. 페이지 넘김

`--days 1 --max-pages 5 --no-snapshot` (2026-09-19):

```
  2026-09-19    1페이지   100건   누적    100건
  2026-09-19    2페이지   100건   누적    200건
  2026-09-19    3페이지   100건   누적    300건
  2026-09-19    4페이지   100건   누적    400건
  2026-09-19    5페이지   100건   누적    500건
  모두 500건   요청 5회   50초
  골프장 118곳
```

5페이지가 **서로 다른 내용**입니다. `pageNum` 이 먹습니다. body 파라미터 이름은 그대로 맞습니다.
(1페이지만으로는 골프장 47곳이었는데 5페이지에서 118곳으로 늘어난 것도 페이지가
실제로 넘어갔다는 증거입니다. 같은 내용을 5번 받았다면 `stop_when_repeated` 가
2페이지에서 멈췄을 것입니다.)

### 마지막 페이지를 넘겼을 때 — **빈 표를 줍니다** (반복 아님)

2026-09-19 은 전체 10,087건 = 101페이지입니다. 직접 `curl` 로 확인했습니다:

| pageNum | 데이터 행 수 | 응답 크기 |
|---|---|---|
| 101 (마지막) | 87 | 123,103바이트 |
| 102 | 0 | 3,446바이트 |
| 103 | 0 | 3,446바이트 |
| 200 | 0 | 3,446바이트 |

102·103·200 페이지 응답은 **md5가 서로 완전히 같습니다**(`dd9ff7f8…`). 머리글(`<thead>`)만
있고 `<tbody>` 가 비어 있는 표를 돌려줍니다. 마지막 페이지를 반복해서 주지 않습니다.
따라서 `pages.stop_when_empty` 가 정상 동작하며, `stop_when_repeated` 는
이 사이트에서는 발동할 일이 없습니다.

100건 × 100페이지 + 87건 = 10,087건으로 사이트가 표시한 전체 건수와 정확히 맞습니다.
